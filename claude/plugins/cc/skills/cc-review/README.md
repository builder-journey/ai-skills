# cc-review — 지시부 텍스트 점검

클로드를 조종하는 **텍스트**가 지금 기준으로 잘 쓰였는지 본다.
CLAUDE.md · `.claude/rules/` · `SKILL.md` · 에이전트 정의.

**판정 기준을 저장하지 않는다.** 실행할 때마다 공식 문서를 그 자리에서 읽어 기준으로 삼는다.

## 왜 기준을 저장하지 않나

Claude Code 는 하루 한두 개꼴로 릴리스된다 (실측: 10일에 12개).
안티패턴 목록을 파일에 박아두면 몇 주 만에 틀린 지적을 하기 시작한다.

실제로 겪은 사례 — 하드코딩한 "알려진 설정 키" 목록은 작성 직후부터 오탐을 냈다.
새 키가 계속 생기고, 문서 목록이 CLI 보다 뒤처지기 때문이다.

그래서 이 스킬이 갖는 건 **방법**(무엇을 물을지)이고,
**기준**(그 답이 무엇인지)은 매번 문서에서 가져온다.

## 설치

```bash
/plugin marketplace add builder-journey/ai-skills
/plugin install bj-cc@builder-journey
```

## 사용

```
설정 점검해줘
CLAUDE.md 괜찮은지 봐줘
```

또는:

```
/bj-cc:cc-review              # 현재 디렉토리
/bj-cc:cc-review ~/ws/myproj  # 특정 프로젝트
```

수집기만 따로 돌릴 수도 있다:

```bash
bash collect.sh          # 사람이 읽는 표
bash collect.sh --json   # 판정 에이전트용
```

## 동작

```
1. collect.sh          지시부 파일 인벤토리 (판정 없음)
        ↓
2. cc-review-judge     서브에이전트 (격리 컨텍스트)
     ├ 공식 문서 6개를 지금 WebFetch
     ├ 대상 파일 직접 읽기
     └ 고정 질문 7개로 판정
        ↓
3. 보고 → 승인 → 건별 수정
```

문서 fetch 를 서브에이전트 안에서 하는 이유: 문서 본문이 네 대화 컨텍스트를 먹지 않는다.

### 던지는 질문 7개

| # | 질문 |
|---|---|
| 1 | 로드 시점이 내용과 맞나? (상시 로드인데 가끔만 필요한가) |
| 2 | 강제력이 필요한가? (도구·명령 금지는 훅·권한이 맞는 자리) |
| 3 | 문서가 명시한 크기·구조 기준을 넘나? |
| 4 | 코드·git 에서 유추 가능한가? |
| 5 | 서로 모순되나? |
| 6 | description 이 트리거로 작동하나? |
| 7 | **문서에 새로 생긴 권장사항 중 적용할 게 있나?** |

7번이 이 스킬의 이유다. "틀렸다"가 아니라 **"지금은 더 나은 방법이 있다"** 를 찾는다.
문서가 업데이트되면 새 제안이 자동으로 나온다.

## 등급

| | 의미 |
|---|---|
| `RED` | 문서가 **명시적으로** 금지·경고한 것을 하고 있다 |
| `YELLOW` | 문서 기준으로 더 나은 방법이 있다. 지금도 동작은 한다 |
| `GREEN` | 문제없다 |

**모든 지적에 출처 URL 과 문서 원문 인용이 붙는다.** 인용을 못 붙이는 지적은 하지 않는다.

## 범위

**본다** — `CLAUDE.md`(전역·프로젝트·로컬·하위 디렉토리) · `AGENTS.md` ·
`.claude/rules/**` · `SKILL.md` · `agents/*.md`

**안 본다** — 권한 · 샌드박스 · `settings.json` 키 · MCP 인벤토리 ·
훅 배관 · 설치 상태 · 버전 · 스킬 사용 빈도

두 번째 목록은 텍스트가 아니거나, 내장 `/doctor` 가 이미 더 잘한다.

## `/doctor` 와 같이 쓰기

겹치지 않는다. 역할이 다르다.

| | `/doctor` (내장) | `cc-review` |
|---|---|---|
| 설치·버전·PATH | ✅ | — |
| 안 쓰는 스킬·MCP·플러그인 | ✅ (사용 카운터 기반) | — |
| 느린 훅 | ✅ (실행 시간 측정) | — |
| CLAUDE.md 자동 정리 | ✅ (고쳐준다) | — |
| **지시문이 최신 기준에 맞나** | — | ✅ |
| **문서 출처·원문 인용** | — | ✅ |
| **새로 생긴 기능 적용 제안** | — | ✅ |

`/doctor` 를 먼저 돌리고, 그 다음 `cc-review` 를 돌리는 순서를 권한다.

## 한계

- 판정은 LLM 이라 **완전히 결정적이지 않다.** 같은 입력에 다른 표현이 나올 수 있다.
  등급이 흔들리면 `reference/sources.md` 의 추출 프롬프트를 더 구체화한다
- 문서 URL 이 바뀌면 `sources.md` 를 갱신해야 한다.
  404 시 `llms.txt` 인덱스로 찾아보지만, 못 찾으면 그 영역은 판정을 건너뛴다
- 매 실행마다 문서를 가져오므로 캐시된 실행보다 느리고 토큰을 더 쓴다.
  이게 설계 의도다 — 낡은 기준으로 틀린 지적을 하느니 비용을 낸다.
  대상에 없는 종류의 문서는 건너뛰고, 각 조회에 출력 상한을 걸어 낭비를 줄인다
- `~/.claude/skills/synced/` (벤더 동기화 스킬)는 사용자가 고칠 수 없어 제외한다

## 파일

| 파일 | 역할 |
|---|---|
| `SKILL.md` | 절차 |
| `collect.sh` | 인벤토리 수집 (읽기 전용, 판정 없음) |
| `reference/sources.md` | 문서 URL + 페이지별 추출 프롬프트 |
| `../../agents/cc-review-judge.md` | 판정 서브에이전트 |
| `tests/run-all.sh` | `collect.sh` 검증 (판정은 테스트 안 함) |
